# fever-clients

Autogenerated client SDKs for the **FEVER Retrieval** appliance API —
the multimodal media database you run from the AWS Marketplace: images, video,
and audio in one table, with hybrid vector + full-text search, dedupe, and a
read-only SQL console over your corpus.

One spec in, eight clients out:

| Language   | Package name              | Directory            |
|------------|---------------------------|----------------------|
| Python     | `fever-client`            | `clients/python`     |
| TypeScript | `fever-client`            | `clients/typescript` |
| Go         | `clients/go` (module)     | `clients/go`         |
| Ruby       | `fever_client`            | `clients/ruby`       |
| Java       | `com.lowdownlabs:fever-client` | `clients/java`   |
| Rust       | `fever-client`            | `clients/rust`       |
| PHP        | `lowdownlabs/fever-client`| `clients/php`        |
| C#         | `LowdownLabs.Fever`       | `clients/csharp`     |

Everything here is generated from [`spec/openapi.json`](spec/openapi.json),
which is a deterministic export of the FastAPI service in the private
[`Lowdown-Labs/lowdown_lab`](https://github.com/Lowdown-Labs) monorepo
(`fever_retrieval/scripts/export_openapi.py`). **Never edit `clients/` by
hand** — change the spec or the generator config and regenerate.

## How a spec change becomes a release

```
lowdown_lab (main)                       fever-clients
─────────────────                        ─────────────────────────────────────
service code changes
   │
   ▼  (workflow: fever-clients-sync)
export_openapi.py ──spec diff?──► opens PR: spec/openapi.json only
                                        │
                                        ▼
                              CI: spec validate + smoke all 8 clients
                              Security: gitleaks, trivy, pip-audit,
                                        npm audit, govulncheck
                                        │
                                        ▼  human merges (CODEOWNERS)
                              Release: version (spec version, patch-bumped)
                                       → regenerate all clients, stamped
                                       → smoke again → commit [skip ci]
                                       → tag vX.Y.Z → artifacts + SBOM
                                       → GitHub Release
```

Nothing ships without: the pinned generator image, green security scans, a
human merge, and a reproducible regeneration (`scripts/generate.sh` output is
diff-verified in CI on every non-spec change).

## Installing from releases

Registries (PyPI, npm, RubyGems, …) come later — the repo goes public at the
same time. Until then, install straight from the GitHub Release assets
(verify against `checksums.txt` first):

```bash
# Python
pip install https://github.com/Lowdown-Labs/fever-clients/releases/download/v0.3.0/fever_client-0.3.0-py3-none-any.whl

# TypeScript / Node
npm install https://github.com/Lowdown-Labs/fever-clients/releases/download/v0.3.0/fever-client-0.3.0.tgz

# Ruby
gem install https://github.com/Lowdown-Labs/fever-clients/releases/download/v0.3.0/fever_client-0.3.0.gem

# Go — no artifact needed, go get the module at a tag
go get github.com/Lowdown-Labs/fever-clients/clients/go@v0.3.0
```

Java (jar), C# (nupkg), Rust and PHP (source drops) attach to the same
release; see the release notes.

## Using a client

Every client maps 1:1 to the spec's operation IDs (`search`, `ingest_media`,
`find_duplicates`, `query`, `create_key`, …). Auth is a bearer API key minted
on your appliance (`POST /v1/keys`, admin console, or the examples in the
docs). Point the client at your appliance URL, pass the key, call `search`:

```python
from fever_client import ApiClient, Configuration, SearchApi
from fever_client.models import SearchRequest

cfg = Configuration(host="https://your-appliance.example.com", access_token="fv_live_...")
hits = SearchApi(ApiClient(cfg)).search(SearchRequest(text="red bicycle", k=10))
```

Full walkthroughs (semantic search, training-data curation, duplicate /
catfisher detection) live in the docs on gimmelowdown.com.

## Trust model

- **Pinned generator**: `scripts/generate.sh` uses
  `openapitools/openapi-generator-cli:v7.25.0@sha256:2ab0a9…` — bump it
  deliberately, in its own reviewed PR.
- **Scans on every PR + weekly**: gitleaks (secrets), Trivy fs (all
  dependency manifests), pip-audit, npm audit, govulncheck.
- **Supply chain per release**: SBOM (`sbom.spdx.json`) + `checksums.txt`.
- **No secrets anywhere**: all workflows run on `GITHUB_TOKEN` with
  least-privilege permissions; the only cross-repo credential is the
  `FEVER_CLIENTS_TOKEN` PAT held by *lowdown_lab*, used to open spec PRs.
- Hardening backlog for going public: pin actions by SHA, enable SARIF
  uploads + code scanning, OpenSSF Scorecard, artifact attestations,
  signed tags.

## Repo layout

```
spec/openapi.json     vendored spec (the only input)
generator/*.yaml      per-language openapi-generator configs
scripts/generate.sh   regenerate clients (CI drift-checks this)
scripts/smoke.sh      per-language build/compile smoke
clients/<lang>/       generated output — DO NOT HAND EDIT
.github/workflows/    ci.yml · security.yml · release.yml
```

## Bumping the generator

1. Pick the new tag + digest on Docker Hub (`openapitools/openapi-generator-cli`).
2. Update `GENERATOR_IMAGE` in `scripts/generate.sh` and the image in
   `.github/workflows/ci.yml`.
3. Run `scripts/generate.sh`, review the full clients diff, open a PR.
