Autogenerated client SDKs for the **FEVER Retrieval** appliance API -
the multimodal media database you run from the AWS Marketplace. Images, video,
audio, and docs in one system, with hybrid vector + full-text search, dedupe, and a
read-only SQL console over your corpus.

One OpenAPI spec in, eight clients out:

| Language   | Package name              | Directory            |
|------------|---------------------------|----------------------|
| Python     | `fever-client`            | `clients/python`     |
| TypeScript | `fever-client`            | `clients/typescript` |
| Go         | `clients/go` (module)     | `clients/go`         |
| Ruby       | `fever_client`            | `clients/ruby`       |
| Java       | `com.lowdownlabs:fever-client` | `clients/java`   |
| Rust       | `fever-client`            | `clients/rust`       |
| PHP        | `lowdownlabs/fever-client`| `clients/php`        |
| C#         | `LowdownLabs.Fever`       | `clients/csharp`     |

Everything here is generated from [`spec/openapi.json`](spec/openapi.json),
which is a deterministic export of our FastAPI service OpenAPI docs.

# Installing from releases

Registries (PyPI, npm, RubyGems, …) will be live later. Until then, install
straight from the GitHub Release assets (verify against `checksums.txt` first):

```bash
# Python
pip install https://github.com/Lowdown-Labs/fever-clients/releases/download/v0.3.0/fever_client-0.3.0-py3-none-any.whl

# TypeScript / Node
npm install https://github.com/Lowdown-Labs/fever-clients/releases/download/v0.3.0/fever-client-0.3.0.tgz

# Ruby
gem install https://github.com/Lowdown-Labs/fever-clients/releases/download/v0.3.0/fever_client-0.3.0.gem

# Go — no artifact needed, go get the module at a tag
go get github.com/Lowdown-Labs/fever-clients/clients/go@v0.3.0
```

Java (jar), C# (nupkg), Rust and PHP (source drops) attach to the same
release; see the release notes.

# Using a client

Every client maps 1:1 to the spec's operation IDs (`search`, `ingest_media`,
`find_duplicates`, `query`, `create_key`, …). Auth is a bearer API key minted
on the appliance. Point the client at the appliance URL, pass the key, call `search`:

```python
from fever_client import ApiClient, Configuration, SearchApi
from fever_client.models import SearchRequest

cfg = Configuration(host="https://your-appliance.example.com", access_token="fv_live_...")
hits = SearchApi(ApiClient(cfg)).search(SearchRequest(text="red bicycle", k=10))
```

Full walkthroughs live in the docs on gimmelowdown.com.

# Trust model

- **Pinned generator**: SDK generator uses
  `openapitools/openapi-generator-cli:v7.25.0@sha256:2ab0a9…`
- **Scans on every PR + weekly**: gitleaks (secrets), Trivy fs (all
  dependency manifests), pip-audit, npm audit, govulncheck.
- **Supply chain per release**: SBOM (`sbom.spdx.json`) + `checksums.txt`.
- **No secrets anywhere**: all workflows run on `GITHUB_TOKEN` with
  least-privilege permissions.
